# 期待値計算仕様

- 対象: Phase 1 Milestone 3
- 更新日: 2026-11-05
- 実装: `src/domain/calculations/`

## 1. 単一オッズの計算

推定的中確率を`p`、観測時点の元本込み十進オッズを`O`、購入予定金額を`S`円とする。計算途中では丸めず、画面表示時だけ丸める。

| 指標 | 計算式 |
|---|---|
| 期待回収率 | `p × O × 100` % |
| 期待払戻金 | `p × O × S` 円 |
| 期待純利益 | `p × O × S − S` 円 |
| 損益分岐的中確率 | `1 / O` |
| 推定確率優位幅 | `p − 1 / O` |

単勝・複勝・枠連・馬連・ワイド・馬単・三連複・三連単の全8券種で同じ期待値式を使う。券種別の必要番号数、順序、枠連ゾロ目はインポートスキーマで検証済みの値を保持し、計算エンジンで組合せを書き換えない。

positive / break_even / negativeの分類は購入金額に依存させず、期待回収倍率`p × O`を1と比較する。浮動小数点誤差を避けるため差の絶対値が`1e-12`以下ならbreak_evenとする。このため購入金額が0円でも、100%超はpositive、100%はbreak_even、100%未満はnegativeになる。期待払戻金と期待純利益の式は変えない。

## 2. 算出拒否

次の場合は`status=unavailable`と理由を返す。未設定値をゼロや既定オッズへ変換しない。

- `p`または`O`が`null`
- `p`が有限値でない、または0〜1の範囲外
- `O`が有限値でない、または1.0未満
- オッズが記録済みでも観測日時がない場合
- `S`が有限値でない、または0円未満

`p=0`は有効な推定値として計算する。`O=1.0`も元返し境界として計算する。

現行JSONの`odds_observed_at`は、オッズを記録した観測日時であり、発売締切後の最終オッズが確定したことを表すフラグではない。Milestone 3では`odds`と`odds_observed_at`が両方ある場合に「観測時点のオッズ」として計算する。

## 3. オッズ範囲

現行JSON v1の`odds`は単一値または`null`であり、複勝・ワイドのオッズ範囲を保存できない。この互換性を変更せず、計算層には`lower`と`upper`を別々に評価する`calculateExpectedValueRange()`を用意する。範囲を平均値などの単一オッズに自動変換しない。

将来のJSONスキーマ更新では、単一値と範囲値を判別できるオッズquote型、上下限それぞれの観測時刻・出典を追加する。既存の`odds: number | null`は移行規則を定義するまで維持する。

## 4. 展開シナリオ加重

展開シナリオ`i`の発生確率を`wᵢ`、その展開における同一馬券の条件付き的中確率を`pᵢ`とする。

```text
総合的中確率 = Σ(wᵢ × pᵢ)
```

`calculateScenarioWeightedProbability()`は、展開確率合計が許容誤差`1e-6`以内で1であり、すべての条件付き的中確率が0〜1で設定済みの場合だけ計算する。

現行JSONには馬券候補ごとの条件付き的中確率がないため、確定予想画面では展開別期待値を未算出と表示する。`horses[].scenario_assessments`から数値を生成しない。将来は`bet_candidates[].scenario_hit_probabilities`相当の明示フィールドをスキーマ版更新で追加し、シナリオIDとの参照整合をZodで検証する。

## 5. 表示と解釈

- 確定予想の候補を期待回収率降順またはJSON登録順で比較できる。
- 算出不能候補はランキング末尾に「未算出」と理由を表示する。
- `confidence=low/unknown`は高い不確実性として文字で表示する。
- 期待回収率が100%を超えても、購入推奨や利益保証として扱わない。
- Milestone 3では100円当たりの比較までとし、資金配分はMilestone 4で実装する。
