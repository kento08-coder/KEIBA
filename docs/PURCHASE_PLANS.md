# 購入プラン生成仕様

- 対象: Phase 1 Milestone 4
- 更新日: 2026-11-05
- アルゴリズム版: `phase1-m4-v1`
- 実装: `src/domain/calculations/purchase-plan.ts`

## 1. 共通条件

- 入力は確定済み予想バージョンの`bet_candidates[]`だけを使用する。
- `hit_probability`、`odds`、`odds_observed_at`が揃い、期待値を算出できる候補だけを自動配分対象にする。
- 自動配分は期待回収倍率`p × O`が1を超える候補だけを使用する。`p=0`、`O=1.0`、期待回収率100%以下は自動購入しない。
- 同じ券種・同じ番号組の重複候補はJSON登録順で最初の1件だけを使用する。
- 購入額は100円単位、総額は予算以下、点数と1点上限を厳守する。予算は使い切らなくてよい。
- 券種は全券種を対象にする自動モードと、ユーザー指定券種だけを対象にする手動モードを持つ。
- 同一入力の並び順と配分規則を固定し、同じ入力から同じ提案を生成する。

期待利益合計は各買い目の期待利益の線形和として計算できる。共同確率がないため、正確なプラン的中確率、全損確率、損益分布、分散は算出しない。全馬券が外れた場合の損失額として使用金額を表示するが、その発生確率は表示しない。

## 2. 期待値重視型

1. プラス期待値候補を期待回収率降順に並べる。
2. 同率なら確信度、JSON登録順、候補IDで決定論的に並べる。
3. 点数上限まで候補を選ぶ。
4. 選択候補へ100円ずつ巡回配分し、予算・1点上限のどれかに達したら停止する。

複数候補がある場合に最高期待値の1点へ全額配分しない。候補が1点しかない場合も1点上限を超えない。

## 3. 保守的ケリー参考型

単一の独立二値馬券について、次を参考比率とする。

```text
f = (p × O − 1) / (O − 1)
参考購入額 = floor100(予算 × f × 縮小係数)
```

- `O <= 1`、`f <= 0`、100円未満は自動配分しない。
- 初期縮小係数は1/4。画面で1/8、1/4、1/2を選択できる。
- 候補ごとの参考額を100円単位で切り捨て、期待ケリー比率順に予算・点数・1点上限を適用する。
- 複数馬券の比率を単純に合算した結果は、相関を考慮した最適配分ではない。

例: `p=0.8`、`O=2.0`なら`f=0.6`。予算1,000円、1/4ケリーでは150円を100円へ切り捨てる。

## 4. 損失抑制型

- `confidence=high/medium`かつプラス期待値の候補だけを対象にする。
- 使用上限は設定予算の指定割合（初期30%）を100円単位で切り捨てた額とする。
- 最大3点とし、同じ馬番を共有する候補は自動選択時に同時採用しない。枠連同士は枠番で比較し、枠番と馬番を混同しない。
- 選択スコアは推定的中確率、確信度、上限1.5に制限した期待回収倍率から計算する。極端な高オッズだけを優先しない。
- 選択候補へ100円ずつ巡回配分する。

共有番号による判定は重なりの定性的な参考指標であり、統計的相関係数ではない。候補がすべて同じ軸へ依存する場合は選択点数を減らし、予算を未使用のまま残す。

## 5. 手動調整

自動生成後、候補の除外・追加、購入金額、プラン名、メモを変更できる。変更のたびに期待払戻、期待純利益、期待回収率、使用額、未使用額を再計算する。

- 購入額は0円以上の100円単位。0円は除外と同じ扱い。
- 同一候補の重複、点数上限超過、1点上限超過、予算超過は保存不可。
- 期待値未算出候補は購入プランへ追加不可。
- 非プラス期待値やlow/unknown確信度を手動追加した場合は警告する。

## 6. 展開シナリオ

画面にはシナリオ発生確率、ペース、根拠、各馬の`scenario_assessments`、馬券候補の根拠を表示する。現行JSON v1には馬券ごとの展開別条件付き的中確率がないため、各馬評価から数値を生成しない。

将来`bet_candidates[].scenario_hit_probabilities`相当をスキーマ更新で追加した場合、Milestone 3の加重確率関数へ接続できる。スキーマ更新までは展開別プランを定性的な注意表示に限定する。

## 7. Firestore保存

`/users/{uid}/races/{raceId}/plans/{planId}`へcreate-onlyで保存する。

- `sourcePredictionVersionId`
- `planId`、`name`、`memo`、`authorUid`、`createdAt`
- `strategy`、`budgetYen`、設定値スナップショット
- `candidateSnapshot`（確率・観測時点オッズ・観測日時・確信度・根拠）
- `allocations`（購入額と計算結果）
- `summary`、`assumptions`、`warnings`
- `algorithmVersion=phase1-m4-v1`
- `isSimulation=true`

保存transactionで元の確定予想が存在することと同じ`planId`が未保存であることを確認する。Security Rulesでも参照先が確定予想であることを検証し、update/deleteを拒否する。再調整時は新しい`planId`で保存する。これにより元予想や後日のオッズ変更で過去プランを書き換えない。
